🛡️ 灵溪识险 — 完整识别流程

从拍照到结果展示 · 七步流水线 · 三层判定架构

第一阶段 · 本地预处理
1
Step 1 · 本地
📸 拍照 / 选图 → Base64 编码
用户通过「拍照识别」按钮或「相册上传」选择图片。小程序调用 wx.chooseImage 获取临时路径，再通过 uni.getFileSystemManager().readFile 将图片转换为 Base64 编码字符串。
无后端存储
纯本地处理
输入: imagePath (小程序临时路径) 输出: data:image/jpeg;base64,/9j/4AAQSkZJRg...
2
Step 2 · 本地
🔍 图片指纹 Hash → 查缓存
对 Base64 前 500 字符做 SHA-256 哈希指纹。查询 localStorage：已分析过的图片直接返回缓存结果，零 API 调用。
缓存策略：最多 50 条 / 过期 7 天 / 可手动清除。
零 Token 消耗
最多省 100% 成本
✅ 缓存命中
直接返回历史结果，跳过后续全部步骤
展示带有「来自缓存」标记的结果页
❌ 未命中
继续向下，进入 AI 分析流程
第二阶段 · 大模型一次调用（核心）
3
Step 3 · 云端
🧠 GLM-4.6V 模型一次调用
这是整个系统的核心环节。一次 API 调用同时完成三项任务，无需分步调用：
① OCR 文字提取
直接"看"图片，提取图中所有文字，标注风险关键词
② 风险等级分析
基于 System Prompt 中的判定规则，输出 low / caution / high
③ 案例语义匹配
将图片内容与 50 条案例库做语义比对，判断是否同一诈骗套路

📋 System Prompt 结构（注入给 LLM 的完整上下文）

角色设定金融反诈分析助手
8 项任务OCR 提取 → 关键词标注 → 风险定级 → 风险类型 → 风险原因 → 老人版解释 → 案例匹配 → 防骗建议
判定规则10 类 high 触发条件 + 5 类 caution 触发条件 + 3 条 low 安全措辞规则
案例库50 条真实诈骗案例全文（≤50 条时全量注入，>50 条时 N-gram 候选）
输出约束严格 JSON，不含 markdown 标记，各字段字数上限，caseMatch 放在 suggestions 之前
POST https://open.bigmodel.cn/api/paas/v4/chat/completions { "model": "glm-4.6v", "temperature": 0.1, "max_tokens": 2048, "stream": false, "response_format": { "type": "json_object" }, "messages": [ { "role": "system", "content": "你是金融反诈分析助手。用户发送图片...【含50条案例库 + 判定规则】" }, { "role": "user", "content": [ { "type": "image_url", "image_url": { "url": "data:image/jpeg;base64,..." } }, { "type": "text", "text": "请分析图片中的金融诈骗风险" } ]} ] } → 返回 JSON: { "ocrText": "...", "riskLevel": "high", "riskType": "冒充公检法诈骗", "caseMatch": { "caseId": "case_001", "match": true, "reason": "假冒公安索要保证金" }, "plainExplanation": "老人家，这是骗人的...", "suggestions": ["立即拨打96110", ...] }
温度 0.1 (低随机性)
最多重试 3 次
超时 90s
第三阶段 · 后处理修正链（三道防线）
4
Step 4 · 本地
✂️ OCR 文本智能截断
若 LLM 返回的 OCR 文本超过 2500 字，不简单截头去尾，而是保留高风险关键词附近的内容。
节省输出 Token
保留关键上下文
5
Step 5 · 本地
🛡️ 低风险安全措辞过滤
禁止 LLM 在 low 结果中使用绝对安全表述，避免给老人错误的绝对安全感。

关键词替换表

❌ 禁止出现✅ 强制替换为
内容安全未发现明显风险
可以放心建议进一步核实信息来源
无风险请勿完全依赖系统判断
完全可信 / 绝对安全低风险 ≠ 无风险
6
Step 6 · 本地
🔗 案例语义匹配后处理
LLM 的 caseMatch 结果经过多重校验和兜底处理：
✅ LLM match=true + 有效 caseId
绑定案例详情：标题 + 分类 + 简要描述
触发风险升级逻辑
⚠️ LLM 未返回 caseMatch 字段
启用本地关键词兜底引擎
OCR 文本 → 命中 30%+ 关键词 → 匹配
// 风险升级逻辑 if (matchedCase && riskLevel === 'caution') { riskLevel = 'high' // 🔥 案例匹配触发升级 console.log('案例匹配触发风险升级: caution → high') }
7
Step 7 · 本地
💾 缓存结果 + 数据统一标准化
分析结果写入 localStorage（key = 图片 Hash 指纹），下次相同图片直接命中缓存。
normalizeResult() 做最后的字段兼容：snake_case ↔ camelCase、类型安全转换、字数截断。
最多 50 条缓存
7 天过期
第四阶段 · 异常兜底路径
🛡
API 异常 · 多层兜底
⚡ 即使 API 崩溃，用户也能拿到结果
异常场景兜底策略
网络断开 显示网络错误提示 + 引导重试按钮
API 超时 (>90s) 最多重试 3 次（2s/4s/6s 递增延迟）→ 仍失败走完全兜底
JSON 解析全部失败 fallbackFromRawText() — 从原始响应中用正则提取关键词，走本地关键词引擎判断
所有重试均失败 makeEmptyFallbackResult() — 返回 low + 「系统繁忙」提示 + 防骗建议
图片过大 (>10MB) 自动压缩后再发送；超时时在兜底文案中提示
