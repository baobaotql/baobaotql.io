# 灵溪识险 · 开发日志

> **项目**：灵溪识险（Silver Finance Safety Assistant）  
> **类型**：UniApp + Vue 3 微信小程序  
> **定位**：面向老年群体的 AI 金融反诈风险识别  
> **架构**：Serverless（前端直调智谱 GLM-4.6V 多模态大模型，无传统后端）  
> **命名含义**：灵 → 灵敏感知风险 / 溪 → 细水长流守护 / 识险 → 识别风险

---

## 🌱 第一阶段：立项与选型（2026 年 3 月）

### 2026-03-10 · 项目立项

**背景**：老年群体是金融诈骗的高危人群，但市面上缺乏一款真正面向老年人的反诈工具。大多数反诈产品需要年轻人操作、界面复杂、广告多、隐私保护不到位。

**核心命题**：如何让 60 岁以上的老人**自己**能识别一条诈骗信息？

**设计原则**：
- 操作极简：打开 → 拍照 → 看结果，三步完成
- 无需注册：不要求手机号、微信登录
- 大字号 + 高对比度 + 语音播报
- 隐私至上：不上传用户数据、不存储聊天记录

---

### 2026-03-20 · 技术选型

**最终方案**：UniApp + Vue 3 微信小程序 + GLM-4.6V 多模态大模型

| 候选方案 | 评价 | 结论 |
|----------|------|------|
| 原生小程序 | 性能最好，但开发效率低 | ❌ |
| React Native | 不支持微信小程序运行环境 | ❌ |
| UniApp (Vue 3) | 跨平台、组件丰富、适老 UI 库多 | ✅ |
| 自建后端 + 大模型 | 需服务器、运维、域名备案 | ❌ |
| 前端直调 API | 零运维、部署极简、按量付费 | ✅ |

**关键决策**：
- **无传统后端**：图片 Base64 → 直传智谱 API → 返回分析结果，中间不经过任何自有服务器
- **智谱 GLM-4.6V**：相比 GPT-4V 成本低、国内部署、中文金融场景识别更强

### 2026-05-22 · 案例库语义匹配引擎（第一版）

**需求**：即使大模型判为安全，如果内容与已知诈骗案例高度相似，应强制升级风险。

**实现**
1. **`src/utils/caseLibrary.js`** — 案例库 + 匹配引擎
   - 20 个精简案例，覆盖 13 种诈骗类型（冒充公检法、客服、投资理财、保健品、刷单……）
   - 每个案例包含：标题、分类、关键词数组、简要描述
   - 匹配引擎：遍历案例 → 关键词命中计数 → 返回最高分匹配
   - 性能：**纯本地字符串比对，零网络请求、零 token 消耗**

2. **匹配三级规则**：
| 级别 | 条件 | 动作 |
|------|------|------|
| 强匹配 | ≥2 个关键词 | **强制升级为高危** + 展示案例 |
| 弱匹配+高危 | 1 个 + 大模型已判危险 | 确认匹配 |
| 弱匹配·提示 | 1 个 + 大模型未判危险 | 仅提示不升级 |

**示例链路**：
```
用户收到短信：
  「您的医保卡已锁定，请点击链接验证，输入银行卡号和验证码」

→ GLM-4.6V 分析：风险等级 caution
→ 案例库扫描：命中「医保卡」「验证码」「银行卡」「点击链接」4 个关键词
→ 强匹配 → 风险升级为 danger → 展示案例「医保卡停用恐吓短信」
```

**文件**：`src/utils/caseLibrary.js`（267 行）

## 🛡️ 第三阶段：安全加固（2026 年 6 月）

### 2026-06-01 · 图片指纹缓存机制

**问题**：同一张图片可能在不同会话中重复分析，浪费 API 调用额度。

**方案**：`src/utils/storage.js` — 基于图片 Base64 前 500 字符做 SHA-256 哈希指纹。

**缓存流程**：
```
图片 → SHA-256(前500字符) → 查 localStorage
  ├── 命中 → 直接返回缓存结果（零 API 调用）
  └── 未命中 → 走正常分析流程 → 存入缓存
```

**缓存策略**：
- 最多缓存 50 条
- 过期时间 7 天
- 可手动清除

**文件**：`src/utils/storage.js`

### 2026-06-18 · 风险识别完整链路（三层架构总览）

整个系统的风险识别是 **三层架构**：LLM 主路径 → 关键词兜底 → 后处理修正。

#### 第一层：GLM-4.6V 视觉模型主判（核心）

所有风险识别的主体逻辑由 **系统提示词中的规则** 驱动，LLM 一次性完成 OCR + 风险分析 + 案例匹配：

```
图片 → Base64 → GLM-4.6V (含 50 条完整案例库 + 判定规则)
→ LLM 返回 JSON { ocrText, riskLevel, riskType, riskReason, suggestions, caseMatch }
```

**风险等级判定规则（写在 system prompt 里，LLM 直接执行）：**

| 等级 | 触发条件 |
|---|---|
| **high** 高风险 | 命中以下任意一条：索要验证码/密码/银行卡号；要求转账/汇款/扫码；冒充公检法/银行/客服；声称涉嫌犯罪/通缉/冻结账户；含恶意链接/要求下载不明APP/屏幕共享；兼职刷单/日赚/荐股/内幕消息；无抵押贷款/征信修复；中奖需手续费/发展下线；针对老人：特效药/保健品/子女出事；威胁性语言 |
| **caution** 需谨慎 | 承诺高收益保本但不直接索要资金；限时限量/内部名额但无转账指令；免费领取/红包诱导但未索敏感信息；投资推荐但非明确杀猪盘套路 |
| **low** 低风险 | 常规信息/无诱导/无敏感词；反诈宣传/防骗提醒/安全公告 → caseMatch 强制 false |

**案例语义匹配规则（同样由 LLM 语义判断）：**
- LLM 将图片内容与 50 条案例库全文做语义比对
- `match=true` + 正确的 `caseId` → 展示匹配案例
- 反诈宣传内容即使关键词重叠也强制 `match=false`

#### 第二层：关键词扫描引擎（API 失败的兜底）

```javascript
function scanRiskKeywords(text) {
  const lower = (text || '').toLowerCase()
  const highHits = HIGH_RISK_KEYWORDS.filter((kw) => lower.includes(kw))
  const cautionHits = CAUTION_KEYWORDS.filter((kw) => lower.includes(kw))
  const safetyHits = SAFETY_KEYWORDS.filter((kw) => lower.includes(kw))
  // ...
}
```

判定优先级：

```
反诈宣教词 ≥ 2 个？
  └─ 是 → low（即使命中大量风险词也忽略）
  └─ 否 → 高风险词 ≥ 1 个？
           └─ 是 → high
           └─ 否 → 谨慎词 ≥ 3 个？
                    └─ 是 → high（组合升级）
                    └─ 否 → 谨慎词 ≥ 1 个？
                             └─ 是 → caution
                             └─ 否 → low
```

这个引擎只在 **API 完全崩溃**（网络失败 / JSON 解析全失败 → `fallbackFromRawText`）时才走。

#### 第三层：后处理修正链

LLM 返回结果后，经过三道后处理：

| 步骤 | 做什么 | 风险改写 |
|---|---|---|
| `truncateOcrText` | OCR 文本超过 2500 字时智能截断（保留关键词附近） | 不改等级 |
| `sanitizeLowRiskResult` | low 结果中若出现"内容安全""可以放心"等绝对描述 → 替换为安全措辞 | 不改等级 |
| `processCaseMatch` | LLM 匹配到案例后，**low/caution 自动升级为 high** | **改等级** |

关键：案例匹配触发风险升级的逻辑：

```javascript
  if (matchedCase) {
    sanitized.matchedCase = matchedCase
    // LLM 确认的语义匹配 → 信任 LLM 判断，标记为高风险
    if (sanitized.riskLevel === RISK_LEVEL.LOW || sanitized.riskLevel === RISK_LEVEL.CAUTION) {
      sanitized.riskLevel = RISK_LEVEL.HIGH
    }
  }
```

```
      │  │   │                                     │
      │  │   └─ 否 → 走兜底逻辑                     │
      │  │                                            │
      │  └─ 网络/API 失败 ────────────────────────────┘
      │                    │
      │              关键词扫描引擎
      │              scanRiskKeywords(ocrText)
      │                    │
      │              high/caution/low
      │                    ↓
      │              最终结果 ✅
      │
      └─ 所有重试均失败？
            └─ makeEmptyFallbackResult（完全兜底）
                  → low + 系统繁忙提示
```

#### 一句话总结

**LLM 是主裁判**（一次调用完成 OCR + 风险定级 + 案例匹配），**关键词引擎是替补裁判**（API 挂了才上），**后处理是 VAR 复核**（过滤不安全文案 + 案例匹配触发风险升级）。整个设计倾向 **宁可误判为高也不要漏判**。

### 2026-06-29 · PPT Slide 17 动画修复

### 2026-06-25 · 风险结果免责声明与真实性提醒机制

**背景**：即便系统识别为「低风险」，仍存在以下不可忽视的问题：
1. 图片本身可能是 AI 生成、伪造、篡改的；
2. 图片可能仿冒正规金融机构、政府机构、银行页面；
3. OCR 与 AI 分析只能基于当前图片内容进行判断，无法保证图片真实性；
4. 如果用户完全信任系统结果，可能带来误导风险与法律责任。

---

#### 一、所有风险等级统一增加「真实性提醒」

即便是「低风险」，页面底部也必须固定显示：

> "系统仅对图片内容进行辅助分析，请注意核实图片及信息真实性，谨防 AI 生成、伪造页面或仿冒官方机构信息。"

**要求**：
- 使用灰色小字，但清晰可见
- 支持语音播报
- **所有结果页统一存在**（不分风险等级）

---

#### 二、低风险结果禁止使用绝对安全描述

禁止在低风险结果中出现以下措辞：

| ❌ 禁止 | ✅ 替换为 |
|--------|----------|
| "内容安全" | "未发现明显风险" |
| "可以放心" | "建议进一步核实信息来源" |
| "无风险" | "请勿完全依赖系统判断" |
| "完全可信" | — |

**设计意图**：低风险 ≠ 无风险，避免给老年用户错误的绝对安全感。

---

#### 三、增加「风险结果免责声明」

在结果页底部增加固定声明：

> "本系统仅提供金融风险辅助识别，不构成安全承诺、金融建议或真实性认证。"

**要求**：
- 固定展示，**不可关闭**
- 适老化字体大小
- 与页面风格统一

### 2026-06-25 · Token 消耗与 AI 调用成本优化

**背景**：用户量增长后 API 成本会线性上升，需要在不降低识别质量的前提下，系统性控制 Token 消耗。以下为六项优化措施：

---

#### 一、OCR 文本长度限制

对于超长 OCR 文本：
- 仅保留前 **2000~3000 字**
- 超长部分自动截断
- **优先保留高风险关键词附近内容**（而非简单头部截断）

避免整页长文本直接发送给大模型造成 Token 浪费。

---

#### 二、增加关键词预过滤机制

在调用 AI 大模型**之前**，先使用本地规则引擎扫描关键词库：

| 关键词类型 | 示例 |
|-----------|------|
| 高危动作词 | 转账、验证码、点击链接 |
| 诱导词 | 高收益、保本、稳赚 |
| 目标人群词 | 养老金、养老补贴 |
| 身份冒充词 | 官方账户、公检法、银监会 |

**逻辑**：
- **完全无风险关键词命中** → 降低 AI 调用等级，或直接走轻量分析逻辑
- **命中 ≥1 个关键词** → 走正常 AI 分析流程

---

#### 三、Prompt 精简

当前 Prompt 需要去除：
- 重复的规则描述
- 冗长的身份描述
- 多轮无效上下文

**改为**：固定模板 + 精简输出。

AI 仅需返回 5 个字段的 JSON：

```json
{
  "riskLevel": "safe | caution | danger",
  "riskType": "类型",
  "riskReason": "风险原因",
  "elderExplanation": "老人版解释",
  "antiFraudAdvice": "防骗建议"
}
```

不返回多余文本或额外字段。

---

#### 四、控制输出字数

严格限制 AI 输出各字段长度：

| 字段 | 字数上限 | 说明 |
|------|---------|------|
| `riskReason` | ≤ 80 字 | 风险原因，精炼结论 |
| `elderExplanation` | ≤ 120 字 | 老人版解释，通俗易懂 |
| `antiFraudAdvice` | ≤ 80 字 | 防骗建议，行动导向 |

避免 AI 生成冗长文本，节省输出 Token。

---

#### 五、相同图片结果缓存

对相同图片计算 Hash 指纹，建立缓存机制：

- **已分析过的图片** → 直接返回历史结果
- **避免重复调用** OCR 和 AI 大模型
- 缓存策略：最多 50 条、过期 7 天、可手动清除

---

#### 六、增加轻量分析模式

根据图片内容特征，分级采用不同的分析策略：

| 场景 | 分析策略 |
|------|---------|
| 普通宣传单 | 本地规则判断 |
| 无明显风险文本 | 小模型 / 轻量 Prompt |
| 短文本 | 本地关键词匹配 |
| **高风险场景** | **完整大模型分析** |

---

**设计原则**：
- 不影响当前适老化 UI
- 不改变现有页面主结构
- 所有新增提示符合金融产品审慎原则
- 代码结构可扩展，便于后续增加规则库与风险词库

**文件**：`src/utils/api.js`、`src/utils/constants.js`、`src/utils/storage.js`

### 技术亮点

- **零服务器架构**：前端直调大模型，运维成本为零
- **7 步识别流水线**：大模型初判 → 关键词过滤 → 案例库匹配 → 缓存加速
- **三级案例匹配**：强匹配/弱匹配/提示，纯本地零延迟
- **多层兜底异常处理**：超时/断网/非 JSON/大图/空图，全场景覆盖
- **适老化设计**：16px 最小字号、高对比度色板、大触控区域、语音播报
- **隐私至上**：不存储用户数据、不上传服务器、不共享第三方
